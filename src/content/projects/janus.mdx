Janus is a control plane for browser automation agents, named for the Roman god of doorways because it stands at the threshold between a user's intent and the browser, translating each into the other.

It exposes two endpoints. `POST /api/interact` takes a plain-language instruction, turns it into a plan, executes it through Playwright, and returns a trace of what happened. `GET /api/extract` pulls structured data out of the browser's final page state for a given run.

## Inspectable by Design

The goal is not only an agent that works, but one worth trusting. Every execution produces a trace where each step records its action, latency, status, errors, and a screenshot, so a failed run can be replayed and read rather than guessed at. The core loop:

```
plan → act → observe → recover → extract → trace
```

## Action Vocabulary

The agent is confined to a fixed, schema-validated set of actions rather than arbitrary generated code:

| Action | Description |
|---|---|
| `goto` | Navigate to a URL |
| `click` | Click an element |
| `type` | Type text into an element |
| `press` | Press a key |
| `scroll` | Scroll the page |
| `select` | Select an option |
| `back` | Navigate back |
| `hover` | Hover over an element |
| `screenshot` | Capture the page |
| `upload_file` | Upload a file |
| `confirm_human_checkpoint` | Pause for human approval |

That last action matters most. Some steps should not happen without a person saying yes, so the vocabulary makes stopping a first-class move instead of an afterthought.

## Status

Paused as of June 2026. The action vocabulary and Pydantic schemas are defined and the API surface exists; the Playwright controller and execution engine stopped partway. I moved on to inference engineering, and the honest summary is that Janus reached the design stage rather than a working agent.
