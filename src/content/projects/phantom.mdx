Infrastructure drifts away from its IaC definition because incidents do not wait for a pull request. An engineer resizes an instance at 2am, the stack recovers, and the change never makes it back into version control. Drift accumulates quietly and takes hidden cost, security misconfiguration, and architecture nobody can fully explain along with it.

Existing drift detection stops at the diff. Phantom takes the next step and decides what the diff means.

## The Decision, Not Just the Diff

Every drifted property lands in one of three buckets:

- **Legitimize** — the console change was right. Update the IaC to match the live state.
- **Revert** — the change was harmful. Generate a PR restoring the safe state.
- **Refactor** — directionally correct, poorly executed. Apply an optimized value informed by post-incident metrics.

Telling those apart needs context beyond the template, which is the part Phantom assembles.

## Pipeline

- **Detect** — A Lambda lists stack resources, triggers CloudFormation drift detection, polls to completion, and extracts drifted resources with their property diffs.
- **Gather** — For each drifted resource it pulls CloudTrail events from the last 24 hours to establish who changed what and when, the original safe-state template for architectural intent, Datadog logs, metrics and traces from around the drift window, and cost reference data.
- **Analyze** — The analyzer builds a multi-part prompt from that context and invokes Claude through Amazon Bedrock, producing a per-change decision with a confidence score, natural language reasoning, a cost delta, and a severity classification from low to critical.
- **Rectify** — The rectifier applies each decision to produce a reconciled template and opens a GitHub PR with the recommendations attached.

## Template Surgery

Writing values back into CloudFormation is where this gets fiddly. The rectifier resolves simple properties like `InstanceType`, list indexes like `SecurityGroupIngress[2]`, and tag maps like `Tags[ManagedBy]`, while preserving intrinsic functions such as `!Ref`, `!GetAtt`, and `!Sub` rather than flattening them into literals on the way out.

## What I Built

Built the whole pipeline: the drift detection Lambda and its CloudTrail correlation, the Datadog integration supplying observability context, the Bedrock prompt construction that turns five separate data sources into one decision, and the rectifier that applies decisions back into YAML without destroying intrinsic functions.
